# Publishing RENA-RUNE

## Repository contents

Publish source code, the default model configuration, dependency list, documentation, and the Safetensors exporter. Do not publish local training logs, checkpoints, data, tokenizer files, temporary outputs, environment configuration, or diagnostic artifacts in the source repository.

The repository `.gitignore` excludes local data and run output. Review the staged file list before committing.

## GitHub Releases

Model releases should be separate from source-code commits. A release package contains:

- `model.safetensors` - inference weights
- `config.json` - sanitized model and inference configuration
- `tokenizer.json` - matching tokenizer
- `metadata.json` - export metadata

These files are generated by `tools/export_safetensors.py`. Keep full training checkpoints private/local; they include optimizer and training state.

## Release checks

- Run configuration validation and the smoke test.
- Export the selected checkpoint to Safetensors.
- Load the release weights and generate a sample with the release tokenizer.
- Check file sizes and SHA-256 hashes.
- Verify the staged source list contains no local data, run directories, checkpoints, credentials, or machine-specific paths.
- Include the model architecture, parameter count, training-data description, intended use, limitations, and known issues in release notes.
- Confirm the dataset and model-weight redistribution terms before uploading model assets. Code licensing does not automatically cover dataset-derived artifacts.

## Branch policy

Keep this model line isolated from other RENA projects. Changes and release assets in this repository should only cover RENA-RUNE.
